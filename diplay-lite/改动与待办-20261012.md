## 无线连接提速定案（20261012 晚，TS7 实测，versionCode 65/66）

背景：10-12 TS7 三份日志（204308 vc65 / 205800 vc66）+ 0.2.6-ch 四样本对比。vc64 基线 104~107s（首轮必失败 2 轮）；根因链 = BT profile proxy 查询 8s + First TCP 看门狗 30s 恰好杀在 iPhone 入网途中（实测入网 25~35s）+ 每轮失败 teardown 拆热点把 iPhone 踢下网 + Bonjour start/close 各阻塞 7~8s。

- vc65（1.1.4）：①BT 单台直选（唯一 bonded iPhone 跳过 HFP/A2DP profile proxy，省 ~8s）；②First TCP 看门狗 30s 后加 35s 宽限复查，窗口内 TCP 进入即放行；③重试/看门狗失败路径 `closeWirelessStack(keepHotspotForReuse=true)`，热点常开 iPhone 不掉网（对齐 0.2.6 模式）；④Bonjour close 异步化（goodbye 限时 300ms）。实测 Manual 15.4s / Relay 17.3s，失败循环消失
- vc66（1.1.4）：Bonjour start() 整体后台化（204308 日志坐实 JmDNS create+register 同步 7.5s 才是关键路径真凶；BT 快路径已生效后空隙仍在）。竞态护栏：代次过期自查 close / lifecycleLock 兜底 / bonjour 字段引用比较。实测 Manual **11.5s** / Relay **13.3s**，已贴 0.2.6 水平（4.6~12.1s）
- 遗留：`bt socket closed, read return: -1`（iPhone 收流后关引导链）仍会偶发掉线，靠手点重连恢复——归入隧道提级专项

## TS7 有线 CarPlay 突破（20261013 晚，vc68→vc75，✅ 已全线打通）

### 根因链（四层，全部实测实锤）
1. **iOS16.x 在 NCM 链路上必须 mDNS 发现 `_airplay._tcp`/`_raop._tcp` 才起数据面**——0x4301 直给的 fe80::2:7100 不被采用（包级实锤：iPhone 在 NCM 上发 mDNS 查询 4 次，t=43.6s 起）
2. **MUSB EP 0x07 TX 静默丢弃**：配置 6 有两对 NCM 接口组（3/4 组 OUT=0x06 带 interrupt EP 0x87；5/6 组 OUT=0x07 无 interrupt EP）。Lite 原选 5/6 组，iPhone 永远收不到帧；0.2.6-ch 在 TS7 死于自己的 UsbRequest.queue 16KB 上限崩溃（MUSB 特有约束，K60 无此约束、ch 在 K60 正常）未构成对照。vc70 反转选组后 iPhone 首次真实连入（tcp→7100 + 1500B 视频帧）
3. **MUSB RX 高流量/静态期丢包致 NTB16 字节流错位**（每次丢 3 字节，头部多为 000000）：一次签名校验失败即 failSession 拆桥（vc71 实测：画面已出、activeStreams=[110]，满流时一包毁全会话）
4. **内核 cdc_ncm 每 2-4s 重绑 6.3**：与 App usbfs claim 打架（内核侧额外控制传输），PC 外置解绑循环（2s 巡检）期间会话稳定

### 各版本修复
- **vc68**：新增 WiredBonjourAdvertiser——有线模式在 tun 地址（fe80::2）上 JmDNS 注册 `_airplay._tcp`+`_raop._tcp`（TXT 与无线一致），后台线程启动非致命降级
- **vc69**：建立看门狗 15s→30s（JmDNS 注册实测 ~10s，15s 只剩 5s 应答窗口）
- **vc70**：NcmUsbBridge 选组反转为优先 3/4（OUT=0x06 + interrupt EP 0x87）+ 内核 cdc_ncm 解绑外置循环 → **iPhone 首次连入，画面首现**
- **vc71**：看门狗 30s→60s——iPhone 在 TS7 的 mDNS 问答收敛要 ~30s，30s 上限在数据到达前 57ms 误杀（19:51:20 实测）
- **vc72**：NTB16 失步重同步——签名校验失败不再 failSession，向前扫描丢错位前缀对齐下一签名（保留尾 3 字节拼接），丢帧花屏由 keyframe recovery 兜底
- **vc73**：风暴计数窗口化——累计 64 上限在静态画面期（错位 ~1-2 次/秒）2.5 分钟自拆（20:26:18 实测），改为 30s 无错位重置 + 窗口 256
- **vc74/75**：WiredNcmGuard 内置守护（2s 扫 /sys/bus/usb/devices，su 写 driver/unbind，无 root 静默降级）——vc74 曾解绑全部 6.x 导致已 claim 的 6.4 被解绑、alt 复位打死 bulk-out（"bulk-out not ready" 两窗口全超时），vc75 收窄为只解绑 6.3（外置守护的成功行为）

### 残留风险与后续
- **[明日测试] vc76 守护关闭差分实验（无 root 可行性裁决）**：出 guard-off 版，重插 iPhone → 建立 → 正常操作 10min + 静态 10min。稳定 → TS7 有线无 root 也能跑通（分发意义：用户免刷 root 即用）；出现 bulk-out not ready / 建立失败 → 守护必需。依据：vc75 运行中内核绑定 6.3 的 2-4s 窗口内会话无损，④ 守护大概率非必需
