# 日志探针清单（可剥离）

> 维护约定：新增探针必须登记本文件；剥离时勾掉对应条目并注明版本。
> 所有探针输出统一走 LiteLog（文件日志，设置页可预览/导出/Gitee 上传），无独立上报通道。

## 一、常驻自动探针（无 UI，默认运行）

### 1. 蓝牙 A2DP/HFP 状态探针（bt）
- **来源**：1.1.2-test（bt_audio 模式观测点）
- **位置**：`app/.../lite/LiteSessionService.kt` — `btProbeReceiver` + `registerBtProbe()` / `unregisterBtProbe()`
- **触发**：会话服务 onStartCommand 注册，onDestroy 注销
- **内容**：监听 `ACTION_CONNECTION_STATE_CHANGED`（A2DP/HFP），记连接状态与设备地址
- **TAG**：`bt`
- **剥离**：删两个方法与两处调用（onStartCommand 的 `registerBtProbe()`、onDestroy 的 `unregisterBtProbe()`）

### 2. 有线 USB 内核取证探针（usbfx）
- **来源**：vc96（FE-6 20261017 断链取证）；vc97⑤ 内核时间戳水位去重
- **位置**：`app/.../lite/WiredUsbForensics.kt`（独立文件）+ LiteSessionService 三处调用
- **触发**：会话服务 onStartCommand `start()`（su 可用才启动，无 root 静默关闭）；onDestroy `stop()`；AirPlay 断链/wedge 事件时 `snapshot()`（onDebugLog 里匹配 `ncm inbound stalled` / `wired NCM bridge error`）
- **内容**：每 2s 增量拉 `su -c dmesg` 过滤 USB/NCM/host 控制器行；wedge 时抓 sysfs 设备树快照
- **TAG**：`usbfx`
- **剥离**：删 WiredUsbForensics.kt + LiteSessionService 中 `WiredUsbForensics.start()/stop()`、onDebugLog 里的 snapshot 线程块

### 3. 副屏探测探针（cluster）
- **来源**：vc102（仪表/HUD 投射路线判生死，20261018 定案做默认日志检测无按钮）
- **位置**：`app/.../lite/ClusterDisplayProbe.kt`（独立文件）+ 两处调用
- **触发**：MainActivity.onCreate + 会话服务 onStartCommand（捕捉倒车屏等动态副屏）
- **内容**：DisplayManager 全量枚举（id/name/分辨率/flags/state/presentation）→ 三态判定（仅主屏 / PRESENTATION 直投候选 / overlay 候选）；尽力 `dumpsys display` 摘要（无 DUMP 权限记一行失败，属预期）
- **TAG**：`cluster`
- **剥离**：删 ClusterDisplayProbe.kt + MainActivity L209、LiteSessionService L186 两处 `ClusterDisplayProbe.probe(...)`
- **判读**：搜 `cluster` 标签，「判定：」行即结论；PRESENTATION 候选=立项仪表投屏，仅主屏=路线归档

**日志输出格式示例**（LiteLog 行格式 `MM-dd HH:mm:ss.SSS [TAG] 消息`；flags 值：0x0=无标志，0x1=FLAG_PRESENTATION，0x5=PRESENTATION|PRIVATE 私有屏；state：1=OFF 2=ON）：

场景 A — 仅主屏（T3/FE-6 预期形态，路线归档）：
```
10-18 10:30:00.123 [cluster] 副屏探测 begin model=AC8227-NT3 api=28 count=1
10-18 10:30:00.135 [cluster] display id=0 name=内置屏幕 1024x600 flags=0x0 state=2 presentation=false primary=true valid=true
10-18 10:30:00.140 [cluster] 判定：仅主屏：无副屏可投（仪表/HUD 投射路线不可用）
10-18 10:30:00.220 [cluster] dumpsys 摘要 begin
10-18 10:30:00.221 [cluster] mBaseDisplayInfo=DisplayInfo{"内置屏幕, displayId 0", ... real 1024 x 600, ... owner ... (uid 1000) ...
10-18 10:30:00.222 [cluster] dumpsys 摘要 end
10-18 10:30:00.223 [cluster] 副屏探测 end
```

场景 B — PRESENTATION 公开副屏（BYD DiLink5 式，立项形态）：
```
10-18 10:30:00.123 [cluster] 副屏探测 begin model=BYD-Han api=29 count=2
10-18 10:30:00.135 [cluster] display id=0 name=内置屏幕 1920x1080 flags=0x0 state=2 presentation=false primary=true valid=true
10-18 10:30:00.136 [cluster] display id=2 name=fission_bg_xdjaVirtualSurface 1920x720 flags=0x1 state=2 presentation=true primary=false valid=true
10-18 10:30:00.140 [cluster] 判定：副屏可用：PRESENTATION 屏（Presentation 直投候选=2:fission_bg_xdjaVirtualSurface）
```

场景 C — 私有逻辑副屏（overlay/独立窗口候选，需实车验证权限与可见性）：
```
10-18 10:30:00.136 [cluster] display id=2 name=overlay://2 1280x480 flags=0x5 state=2 presentation=true primary=false valid=true
10-18 10:30:00.140 [cluster] 判定：副屏可用：普通逻辑屏（overlay/独立窗口候选=2:overlay://2）
```

边界与失败形态：
```
10-18 10:30:00.110 [cluster] 副屏探测：API 16 < 17，系统无 Display 枚举能力        ← API 护栏
10-18 10:30:00.118 [cluster] dumpsys display：无匹配行（无 DUMP 权限属预期）      ← dumpsys 被拒，枚举结果仍有效
10-18 10:30:00.131 [cluster] 副屏探测异常 SecurityException: xxx                  ← 探针自身异常，不影响主流程
```

判读要点：`count=` 一眼定生死（1=归档，≥2=看 flags 分形态）；`dumpsys 摘要` 的 `owner <包名> (uid ...)` 是 fork AdbClusterRouter 建静态表的依据（如 `com.xdja.containerservice`/`com.byd.containerservice`），对照 carlito fork 的 displayId 匹配规则可直接复用。

### 4. 状态栏探针（statusbar）
- **来源**：vc102（AC822X 反馈 vc101 状态栏隐藏无效，取证顶栏归属）
- **位置**：`app/.../lite/StatusBarProbe.kt`（独立文件）+ 三处调用
- **触发**：MainActivity onCreate（"onCreate"）+ 3 秒后（"t+3s"，对比回弹）+ 会话服务 onStartCommand（"session-start"）
- **内容**：①UI 回读：systemUiVisibility 设置值 vs 系统回读值（ROM 忽略/改回即实锤）、windowFlags、status_bar_height 资源、屏高 vs App 可用高差；②`dumpsys window` 全窗口清单（Window #/mOwnerUid/mBaseLayer/mAttrs）——判定顶栏是标准 StatusBar 还是厂商自绘 overlay
- **TAG**：`statusbar`
- **剥离**：删 StatusBarProbe.kt + MainActivity 两处、LiteSessionService 一处调用
- **判读**：onCreate 与 t+3s 两轮「回读systemUi」不等=系统改回（systemUiVisibility 被忽略）；窗口清单里搜 `mAttrs` 带 TYPE_APPLICATION_OVERLAY(0x7e5)/TYPE_SYSTEM_OVERLAY(0x7e6) 的非 systemui 包名=厂商自绘栏（systemUiVisibility 永远管不着，需 overlay 覆盖或 root 隐藏）

## 三、手动触发探针（UI 入口）

### 5. 数据流抓包（pcap）
- **来源**：fe6t1（NCM 数据面 wedge/黑边取证）
- **位置**：`shared/.../transport/PcapTap.kt` + SettingsPage 开关行（「数据流抓包」状态行）
- **触发**：设置页手动开/关
- **内容**：NCM 桥入/出站以太网帧环形落盘（3 文件 × 32MB 滚动覆盖），存 `Android/data/<pkg>/files/pcap/`，Wireshark 直读
- **剥离**：删 PcapTap.kt + SettingsPage 的 pcapStatus/pcapRow 块与 import

### 6. 系统诊断后台取证（diag）
- **来源**：1.0.29 起，1.1.4 重做
- **位置**：`app/.../lite/Diagnostics.kt` — `collectForensics()`（private）
- **触发**：设置页「系统诊断」完整复测完成后静默执行（快检不跑）
- **内容**：蓝牙栈状态/getprop 过滤/ps/USB 拓扑 uevent/su 指纹+strings+base64 导出/dmesg 尾部/网络 ADB 直试
- **TAG**：`diag`
- **剥离**：删 collectForensics() + fullCheck 末尾调用行（诊断 UI 本体保留）

## 四、兼有功能职责的观察点（剥离需注意）

### 7. 方控 KeyEvent 监听（ui）
- **来源**：fe6t2（FE-6 方控取证）；**vc87 起兼派发职责，不能整块删**
- **位置**：`app/.../lite/MainActivity.kt` — `dispatchKeyEvent()` override
- **内容**：全量 KeyEvent 落日志（code/scan/dev/src）；**同时**非学习页转发给 `LiteSteeringKeys.onWindowKeyEvent()`（方控功能主干，vc87 实锤窗口 KeyEvent 是唯一派发通路）
- **剥离**：只删 `LiteLog.log("ui", "方控监听 ...")` 一行，**保留 LiteSteeringKeys 转发**（否则方控全失效）

## 五、诊断辅助（非探针，相关项）

- **网络 ADB 自举**（vc67）：MainActivity `bootstrapNetworkAdb()`，root 下静默把 adbd 拉到 5555。属调试便利功能，非日志探针。
- **LiteLog 本体**：文件日志框架，探针的载体，不剥离。
